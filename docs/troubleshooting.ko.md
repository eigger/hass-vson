# WP6003 문제 해결

[README](../README.ko.md) | [English](troubleshooting.md)

## 공통 문제 해결

먼저 [공통 Bluetooth 문제 해결](https://github.com/eigger/blesession/blob/main/docs/troubleshooting.ko.md)과 [Bluetooth proxy 설정 안내](https://github.com/eigger/blesession/blob/main/docs/bluetooth.ko.md)를 확인하세요.

## 기기별 확인 사항

- 지원 모델은 Vson WP6003이며 `6003#*` 이름과 `fff0` 서비스를 광고합니다. 이번 변경에서 검증한 펌웨어 버전은 없습니다.
- 기기 전원을 유지하고 연결 가능한 로컬 어댑터 또는 활성 Bluetooth proxy 범위 안에 두세요. 별도 깨우기 절차는 구현하거나 검증하지 않았습니다.
- 이 통합은 페어링·본딩·인증을 구성하지 않습니다. 기기 연결을 점유할 수 있는 휴대폰 앱이나 다른 통합을 종료하세요.
- 검색은 수동 광고 수신을 사용합니다. 측정에는 별도의 능동 GATT 연결이 필요합니다. `fff4` 알림을 구독하고 `fff1`에 `0xAB`를 쓴 뒤 18바이트 응답을 받습니다. 검색 성공만으로 이 통신의 성공이 보장되지는 않습니다.
- 기본 폴링 주기는 300초이며 30~86400초로 설정할 수 있습니다. 폴링마다 연결을 포함해 60초로 제한한 라이브러리 시도 1회를 실행하며, 연결기 자체의 연결 재시도 동작은 유지합니다. 응답 대기와 쓰기는 각각 5초 제한입니다. 알림 구독 후 0.5초 대기와 명령 후 0.05초 간격은 기존 기기 타이밍을 유지합니다.
- 매 폴링 후 연결을 닫으므로 폴링 사이에 연결 센서가 연결 끊김을 표시하는 것은 정상입니다. 로컬 어댑터와 proxy 모두 HA Bluetooth 라우팅을 사용합니다. 이번 변경에서 실제 WP6003으로 검증한 경로는 없습니다.

## 증상과 조치

| 증상 | 실패 단계 | 확인 사항 | 조치 |
| --- | --- | --- | --- |
| 기기가 검색되지 않음 | 검색 / `unreachable` | 전원, `6003#*` 광고, `fff0` 서비스, 연결 가능한 수신기 | Bluetooth 설정을 확인하고 전원이 켜진 기기를 가까이 옮기세요. |
| 광고는 보이나 연결되지 않음 | `connect` | proxy 연결 슬롯, 다른 앱의 기기 점유 | 다른 연결을 종료하고 다음 폴링을 기다리세요. |
| 서비스가 다르거나 알림 구독 실패 | `session` / `subscribe` | WP6003 모델, GATT 서비스와 특성 속성 | 모델을 확인하고 계속되면 짧은 디버그 로그를 수집하세요. |
| 연결이 끊기거나 쓰기가 반환되지 않음 | `transfer` / `readout` | proxy 상태, 보고된 경로, 신호와 간섭 | 전송 경로를 복구하고 다음 폴링을 기다리세요. 멈춘 작업에는 시간 제한이 있습니다. |
| 응답이 없거나 패킷이 올바르지 않음 | `transfer` / `readout` | 전원, 18바이트 응답 여부 | 다른 앱을 종료하고 모델·펌웨어와 실패 정보를 제보하세요. |
| 측정 성공 후 연결 종료 실패 | `disconnect_error` 속성 | proxy 또는 어댑터 상태 | 통신 문제 센서의 속성을 확인하세요. 정상 측정값은 유지됩니다. |

## 진단 및 로그

연결, 폴링 시간, 통신 문제, 마지막 오류, 오류 횟수, 마지막 실패 센서를 제공합니다. 연결은 광고 수신 여부가 아닌 활성 GATT 세션을 뜻합니다. 폴링 시간은 기기 조회와 정리를 포함하며 폴링 중에도 갱신됩니다.

통신 문제는 첫 폴링이 끝나기 전에는 알 수 없음이며, 폴링 실패나 정리 경고가 있으면 켜지고 경고 없이 성공하면 꺼집니다. 측정 센서는 폴링 실패 후 사용 불가가 되고 성공 시 복구됩니다. 마지막 오류와 마지막 실패는 복구 후에도 마지막 실패 정보를 유지합니다. 오류 횟수는 항목 설정 이후 실패한 폴링 수이며 다시 로드하거나 재시작하면 초기화됩니다. 취소된 폴링은 실패로 기록하지 않습니다. 측정에 성공한 뒤 발생한 정리 경고는 통신 문제에 표시하지만 폴링 실패 횟수에는 포함하지 않습니다.

가능한 경우 blesession 공통 속성인 `failed_stage`, `failed_detail`, `likely_cause`, `likely_cause_key`, `error`, 단계별 시간, `via`, `via_type`, `rssi`, `paths`를 표시합니다. `via_unconfirmed`가 참이면 `via`는 광고를 가장 잘 수신한 경로를 통한 추정값이며 확인된 연결 경로가 아닙니다. 경로 정보 누락은 알 수 없음을 뜻하며 로컬 연결의 증거가 아닙니다.

Home Assistant에서 `custom_components.vson`과 `blesession`의 디버그 로그를 일시적으로 켜고 한 번 재현한 뒤 끄세요. 해당 구간만 수집하고 공개 전 기기 주소, 스캐너 이름, 인증 정보, 토큰과 개인정보를 제거하세요.

## 문제가 계속되는 경우

기존 [Issues](https://github.com/eigger/hass-vson/issues)로 제보하세요. Home Assistant·통합·blesession·해당하는 ESPHome 버전, 기기와 proxy 모델·리비전·펌웨어, 로컬/proxy 연결 방식, 실패 시각·단계와 재현 절차를 포함하세요. 성공과 실패 사례를 구분해 주세요. 자동 테스트로 실제 하드웨어 동작을 검증한 것은 아닙니다.
